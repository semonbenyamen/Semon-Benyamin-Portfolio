The problem

The Track System has a frontend, a backend, and infrastructure with a different release cycle. A change to an application screen and a change to cloud infrastructure need different checks and permissions.

Project scope

A delivery case study from my DevOps graduation repository.

Application workflow

The app pipeline watches frontend, backend, and chart changes. It defines validation, container builds, and a Helm deployment path for the application.

Infrastructure workflow

A separate Terraform workflow handles infrastructure changes. Its concurrency setting serializes operations that share the same Terraform state.

Architecture documentation

The repository maps the intended AWS environment, including ECR images, workloads on EKS, and a PostgreSQL database on RDS.

Engineering decision

How can a deployment be traced to a source revision?

Both application images are passed to Helm with the Git commit SHA as the tag. The release configuration can refer back to a specific source revision. Separate workflow triggers also mean an infrastructure-only change follows its own validation path.
