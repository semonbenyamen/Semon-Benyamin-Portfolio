The problem

A host-checking API accepts input that will affect a network operation. It needs to distinguish a malformed request from a completed check, communicate failure clearly, and keep internal diagnostics on the server.

My work

Implemented host validation, bounded requests, and structured responses.

Read the request

The Express controller parses XML, extracts the requested host, and checks basic input requirements before handing it to the validation layer.

Bound the check

Implemented destination restrictions and request timeouts. A completed check reports reachability and the time of the check.

Shape the response

The controller formats replies as XML and keeps internal error details in server logs. A caller receives a short, consistent failure message.

Engineering decision

How should the API distinguish “unreachable” from “the check failed”?

Reachability is the result of a completed check. A failure inside the service means the check could not produce that result. The response contract keeps those two cases separate so the interface can explain what happened accurately.
