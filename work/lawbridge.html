The problem

A client needs to find a lawyer and arrange a visit. Staff have a different job: check documents, manage a queue, and decide when a membership can be activated. One legal services platform had to support both journeys without giving everyone the same permissions.

My work

I proposed the idea for LawBridge, led the four-developer team, and built seven REST API modules.

Client services

Built the authentication, lawyer search, appointments, complaints, and dashboard modules. Connected React screens to Express endpoints with Axios.

Association operations

Built the Bar Association services and administration modules, including document verification, multi-stage approval, membership activation, QR check-in, and queues.

Team delivery

Led a four-developer team through implementation, integration, code review, and deployment. Integrated real-time chat and notifications using Socket.IO.

Engineering decision

Which actions belong in a request, and which need a live update?

An approval or appointment changes a stored record and needs a clear response for the person submitting it. I used REST for those operations. Chat and notifications also need to reach someone who already has the app open, so those interactions use Socket.IO.
