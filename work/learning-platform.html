The problem

A student can click Enroll twice, revisit a completed lesson, or return after a session expires. The application has to recognize the same student, preserve one enrollment, and calculate completion from their progress.

My work

I independently developed the Authentication, Enrollment, and Student Progress backend modules and contributed React interfaces to the team’s LMS.

Identity and access

Implemented registration, email verification, access and refresh tokens, password recovery, and role checks for students, instructors, and administrators.

Enrollment and progress

Validated that a course is published. Used PostgreSQL transactions and row-level locking to prevent duplicate enrollments, then tracked lesson progress and calculated course completion.

Frontend integration

Built React interfaces with TanStack Start. Server-side calls connect the UI to the REST API using types generated from the Swagger contract.

Testing and delivery

Refactored Courses, Sections, and Lessons and maintained Vitest coverage across services, controllers, and authorization guards. Documented the API with Swagger/OpenAPI, used Docker Compose locally, and submitted and reviewed GitHub pull requests.

Engineering decision

What happens when two enrollment requests arrive together?

Two requests can both reach an initial check before either has saved its enrollment. I used a transaction and row-level locking so the competing operations can be handled in sequence. The same discipline applies to progress: a repeated lesson update should still represent one completed lesson.
