HR Leave Management System.

The problem

Employees need to submit dates and see their request status. HR needs to review pending requests and account for approved days. The same request should not deduct the leave balance twice.

My work

I worked in a team of four and co-developed JWT authentication, role-based authorization, and the MongoDB-backed leave workflow.

Employee request

The React application captures a leave request. The API associates it with the signed-in employee so they can retrieve their own request history.

HR review

Contributed to role-protected approval workflows and request status tracking. The review controller checks for a pending request and records who processed it.

Leave balances and reports

Co-developed the MongoDB-backed workflow for balance updates and aggregation-based reporting. Approved days reduce the employee’s available leave.

Engineering decision

When should days come off the balance?

A request is only a proposal while it is pending. The review controller changes a pending request to the chosen status, checks the available balance for an approval, and deducts the duration if sufficient days remain. A rejection leaves the balance unchanged.

Outcome & evidence

Employees can submit and track leave, while HR can approve or reject requests and report on their status. The frontend and backend are available in separate repositories.

For a technical conversation

An employee with ten days available requests three days. Compare approval with rejection, then consider what should happen if HR reviews the same request again.
