The problem

An application needs to identify the returning account and decide whether that account can perform a requested operation. A signed-in user can still lack the role a protected operation requires.

My work

Built registration, login, and role-based access for protected operations.

Account entry

Developed registration and login endpoints for the standalone Express API.

Authenticated requests

Implemented JWT-based authentication for requests to protected operations.

Role checks

Applied role-based authorization so that access depends on the role the operation requires.

Engineering decision

What should a successful login establish?

Login establishes the account identity used in later requests. Authorization is a separate decision at a protected operation. Keeping both checks explicit lets two signed-in accounts receive different decisions for the same action.
